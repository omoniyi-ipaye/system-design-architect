# System View Pack: <System>

Use only the views that answer real design/review questions. Keep AS-IS and TARGET state separate.

## 1. System context / boundary
**Question:** What is the system, who participates, and what is outside it?

## 2. End-to-end flow
**Question:** How does work/information/resource move from trigger to outcome?

## 3. Decisions, state, and ownership
**Question:** Who decides what, what state changes, and who owns each transition?

## 4. Capacity / queue / bottleneck view
**Question:** Where can demand exceed capacity or work accumulate?

## 5. Control / risk / failure overlay
**Question:** Where can the system fail, become unsafe, lose control, or propagate harm?

## 6. Feedback / causal-loop view
**Question:** What dynamics reinforce or balance behavior over time?

## 7. Verification / validation view
**Question:** How do we prove implementation correctness and real-world outcome fitness?

## 8. Adaptive operating loop
**Question:** How does the system sense, detect, diagnose, respond, recover, learn, and adapt?

## 9. Current → transition → target
**Question:** How do we move safely from present state to desired state?
